# 机械臂动作工具

本目录存放动作日志、录制/转换工具、镜像工具、旧 `send_data` 播放器和当前 K1 V1.2.6 trigger 使用的 `ramp_action_player`。机械臂控制会向 CAN 发帧；运行前须确认日志所属臂、实际总线、反馈、急停及运动空间。下列路径从仓库根目录执行。

原目录的[动作详细手册](../../../../../docs/用户使用文档/04_xarm_action使用文档.md)保留旧录制、转换和 `send_data` 调用细节；当前 K1 trigger 的规则以本文件和 V1.2.6 README 为准。

## 当前 K1 动作播放

K1 `V1.2.6/chassis_system/can_listener_trigger.sh` 读取 `can2/0x051` 的白色遥控器位协议，再启动本目录的平滑动作播放器；**它不调用下面的旧 `send_data` 自动回放**。动作映射、解锁规则和 systemd 入口以[底盘 V1.2.6 README](../../xarm_chassis/V1.2.6/README.md)为准。播放器在目标机编译，二进制不作为通用发布产物：

```bash
bash publish/modules/src/xarm_action/action/build_ramp_action_player.sh
```

公共日志位于本目录的 `1/` 或 `examples/`，版本目录不复制日志。K1 V1.2.6 trigger 当前默认左臂 `can1`、右臂 `can0`，与 2026-10-12 的 `vlai-Raymond` 实测一致；换机器须重新核实，不可按默认映射盲目播放。播放器会在打开 CAN 前对每条目标总线的机械臂 `0x01`～`0x08` 电机组加非阻塞互斥锁；头、腰的不同 ID 不被它锁住。锁只约束采用相同约定的程序，不能阻止手工 `cansend`、旧 `send_data` 或尚未接入锁的控制器。未核实本机接线与其他发送进程时，不运行动作 trigger 或自启动安装器。

### 有／无夹爪电机的兼容行为

同一播放器默认支持保留原夹爪电机、以及已拆除原夹爪电机的机型，无需修改日志或 trigger 参数：

| 项目 | 当前行为 |
|---|---|
| 参与动作的机械臂 | 7 个关节反馈 `0x011`～`0x017` 必须全部收到，缺任意一个仍中止；单臂动作只检查目标臂，双臂动作分别检查两臂 |
| 夹爪反馈 `0x018` | 可选；保留原有最多 40 次的启动查询窗口，齐全时提前结束；没有夹爪时会等待窗口结束后继续 |
| 收到夹爪反馈 | 用真实位置计算进入动作的 S 曲线，保留原行为；无效位置仍报错 |
| 未收到夹爪反馈 | 警告一次，不读取夹爪缓存状态；用所选日志区间首帧的夹爪目标作为过渡起点，`--probe` 将 J8 标注为 `log target, unmeasured`，不是实测位置 |
| 发送与日志 | 仍保留每组 8 帧，以及原夹爪 `0x08` 的使能、动作和失能指令；没有原夹爪回复不会单独阻止动作 |

程序不能区分“本来没有夹爪”和“原夹爪故障／掉线”，两者都按缺少可选反馈处理。无反馈时无法保证实际存在但失联的夹爪能平滑进入首帧；若设备随后恢复接收，仍可能执行所发送的目标。替换的夹爪或其他设备不得与旧 `0x08` 控制 ID、`0x18` 反馈 ID 冲突；此兼容不代表支持新夹爪协议。CAN 接口或总线发送错误仍可能导致失败，反馈检查也不是整个动作期间的持续在线保证。

启动顺序仍是先使能，再查询反馈，通过后才进入轨迹，不是“所有检查完成前完全不使能”。本次只修改动作播放器，不改变 ROS 控制器、遥操作或 LeRobot 对夹爪数据的要求。更新源码后须在实际运行的目标机重新执行上面的构建脚本，再重启 trigger；本机二进制不要直接作为 Ubuntu 22.04 通用发布产物。

## 录制、转换、镜像（开发工具）

`action_interactive.sh` 提供被动 CAN 录制及动作日志格式转换。先核实是从臂的反馈、臂侧和 CAN 口，再转换；不要把主臂数据当作从臂动作。对动作日志做离线处理时，先使用副本，保留原始日志与对照结果。

`smooth_action.sh` 虽以 `.sh` 命名，实际是 Python 脚本。它按内置左右零位在日志前后加入使能/失能及平滑插值，默认写入同目录的 `_smoothed.log`，不会覆盖原始 `.log`，但**再次运行会覆盖已有同名处理结果**。脚本内的默认目录仍是旧机器的绝对路径；使用前显式选择输入副本，并核对零位是否适用于当前装配。不要仅凭处理完成就直接上机播放。

`mirror_arm.py` 将关节位置按规则镜像，保留使能/失能帧原值；`004` 位置不取反，其余关节按脚本规则处理。离线示例（输入、输出均使用副本）：

```bash
python3 publish/modules/src/xarm_action/action/mirror_arm.py \
  /tmp/Rax-copy.log /tmp/Lax-mirrored.log
```

可追加 `--compare /tmp/Lax-reference.log` 与已有左臂日志对照。镜像结果需要人工复核方向、零位、限位和动作时序，不能将其视为已通过实机验收。

## 旧 `send_data` 入口

`send_data.c` 仍保留用于历史交互播放和命令行回放，但不属于 K1 V1.2.6 trigger 的当前播放路径。需要复现旧流程时，在此目录编译：

```bash
cd publish/modules/src/xarm_action/action
gcc -o send_data send_data.c -lpthread
```

随后可运行 `./send_data` 进入手动菜单；自动模式接受 `-f` 日志、`-c` CAN 接口，双文件时还需 `-f2` 与 `-c2`。旧工具默认接口不是现场接线证明。未经安全审核，不把历史动作样例或旧文档中的绝对路径直接复制到 K1 机器执行。
